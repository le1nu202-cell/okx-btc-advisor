# 估算强平价口径

本项目不读取 OKX 账户、余额、真实仓位、挂单或资金费流水，因此页面只能显示“计划估算强平价”和“实际估算强平价”，不能把结果称为交易所精确强平价。最终结果以 OKX 客户端显示为准。

## 适用假设

- 合约固定为线性 USDT 本位 `BTC-USDT-SWAP`。
- 本轮估算只支持全仓 `CROSS`；选择逐仓时会明确返回“不可用”，不会把全仓权益公式套到逐仓保证金余额。
- 默认只存在 `BTC-USDT-SWAP` 这一项全仓仓位，没有其他全仓或逐仓仓位影响账户权益，也没有待成交挂单占用保证金。`assumeNoOtherPositions=false` 时强平价保持不可用。
- “全仓支持余额基准”是开仓前用于支撑当前单一全仓仓位的账户余额基准，不是扣除仓位或挂单占用后的可用保证金；当前仓位的未实现盈亏由强平公式单独计算。
- 假设没有未知账户级费用或资产折算。程序不会从 OKX 账户读取或核对这些条件。
- 实际估算只使用人工确认的 `actualFills`、实际剩余 BTC、实际加权入场价、已实现盈亏和已发生手续费。
- 实际强平以 OKX 标记价格和账户页面为准。
- 强平边界使用公开标记价评估距离；行情最新成交价不等于强平触发所依据的标记价。标记价缺失或超过 30 秒时，依赖现价的距离百分比、距离等级和先后警告必须为“不可用”。
- 未结算资金费只有在用户明确选择计入并填写金额时才参与估算。
- 公开档位缺失、过期且没有人工维持保证金率时，结果必须为“不可用”。

## 线性合约估算式

定义：

- `s = +1` 表示做多，`s = -1` 表示做空。
- `Q` 为当前剩余 BTC 数量。
- `A` 为后端权威加权入场价。
- `B` 为支持该仓位的权益：全仓支持余额基准 + 额外保证金 + 已实现毛盈亏 - 已发生手续费 - 用户选择计入的未结算资金费。未实现盈亏由 `s × Q × (P - A)` 单独表示，不重复放入余额基准。
- `r` 为当前公开风险档位或人工输入的维持保证金率。
- `f` 为预计强平手续费/平仓成本率；默认跟随 Taker 费率，也可切换为独立手动估计。
- `K` 为维持保证金固定调整额；正数表示额外维持要求。OKX 当前公开 BTC-USDT-SWAP 档位没有返回该字段，因此自动档位使用 `K = 0`，不会猜测。

仓位权益与维持要求分别为：

```text
E(P) = B + s × Q × (P - A)
H(P) = Q × P × (r + f) + K
```

令 `E(P) = H(P)`，得到估算强平价：

```text
P_liq = (s × Q × A + K - B) / (Q × (s - r - f))
```

该形式与 OKX 公布的 USDT 本位线性永续估算关系一致，但项目缺少账户级数据，所以只能作为单一 BTC 仓位假设下的教育性估算。分母无效、数量为零、结果非正数或关键参数缺失时不输出价格。

## 支持余额与强平费率模式

- `crossEquityMode=FOLLOW_EQUITY` 是新计划默认值：全仓支持余额基准始终等于账户权益，修改账户权益时同步。
- `crossEquityMode=MANUAL` 保留用户填写的独立支持余额，和账户权益不一致时由界面提醒但不会自动覆盖。
- `liquidationFeeMode=FOLLOW_TAKER` 是新计划默认值：预计强平费率始终等于 Taker 费率。
- `liquidationFeeMode=MANUAL` 保留独立的强平费率估计。
- 旧 v0.5 JSON 没有模式字段时，独立值若与账户权益或 Taker 不同则迁移为 `MANUAL`；相同或缺失则迁移为对应的跟随模式，避免改变旧计划的经济含义。
- 首次人工确认开仓时把实际仓位的余额基准冻结为 `liquidationEquityBasisUsdt`。之后计算新草稿不会改变当前实际仓位的强平余额基准；旧成交记录缺少该字段时按原计划值惰性兼容。

## 计划与实际场景

计划区域分别展示：

- 只有计划初始仓。
- 完成一次计划加仓后。
- 按计划保本区完成部分减仓后。

实际区域只在存在人工成交时展示，数量和均价不回退到计划数据。部分减仓后仍使用实际成本池的 `averageEntryPrice`，不会用全成本保本价替代入场价，也不会重复扣除已经体现在实际成交价中的滑点。

## 公共参数

自动参数只来自 OKX 免鉴权公共接口：

- [`GET /api/v5/public/instruments`](https://www.okx.com/docs-v5/en/#public-data-rest-api-get-instruments)：合约类型、`ctVal`、最小张数和价格步长。
- [`GET /api/v5/public/position-tiers`](https://www.okx.com/docs-v5/en/#public-data-rest-api-get-position-tiers)：档位张数范围、维持保证金率和公开最大杠杆。
- [`GET /api/v5/public/mark-price`](https://www.okx.com/docs-v5/en/#public-data-rest-api-get-mark-price)：用于显示当前标记价与强平距离。

BTC 数量先按公开 `ctVal` 换算为合约张数，再选择对应档位。公开参数每 6 小时刷新；失败时最多使用 7 天内的缓存并醒目标记陈旧，超期后不再输出自动强平价。AUTO 模式只使用解析后的公开档位：公开接口没有固定维持额时明确采用 `K = 0`，不会沿用用户先前在 MANUAL 模式输入的 MMR 或固定额。页面显示参数来源和更新时间；程序不调用 `/api/v5/account/*`，也不发送 API Key 或签名头。

估算价与现价距离使用两个独立可用性状态。仓位、权益和维持保证金参数完整时，`estimatedLiquidationPrice` 可以继续为可用；但标记价缺失或陈旧时，`referenceMarkStatus` 标记为 `MISSING` 或 `STALE`，`distanceStatus` 为 `UNAVAILABLE`，距离百分比和距离等级返回空值。实时标记价恢复后，后端最多每秒重算并推送一次权威结果，前端不自行复制强平公式。

## 两类风险必须分开

- 账户损失风险仍按到硬止损的净亏损占权益比例分为低、中、高、极高。
- 强平距离风险单独显示为充足、偏近、危险或可能早于止损强平。

前者不代表行情胜率，后者也不保证止损一定能成交。硬止损和强平价接近时，页面只发出红色警告，不会自动修改计划或替用户下单。
