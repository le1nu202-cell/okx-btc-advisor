# v0.6 市场分析验证说明

分析模型：`indicator-regime-v06.0.0`
验证报告模型：`market-validation-v06`

## 当前结论

本验证框架只能提供探索性、point-in-time 的历史描述，不能证明模型已经有效，也不能把 `confidence` 当作真实胜率。

2026-07-15 的实际本地公共 K 线运行结果仍为 `EXPLORATORY_ONLY`，且 `validationPass=false`。4h 与 24h 的 HAC 有效样本低于 30；24h 方向化结果在本次单一 OOS 中明显为负，因此不能声称当前规则具有已验证的预测优势。

无论当前样本输出如何，代码保持：

- `classification=EXPLORATORY_ONLY`
- `validationPass=false`
- 只有一个锁定 OOS 区间
- PBO 与 Deflated Sharpe 不可用

在至少完成预注册多配置试验账本、多个独立 OOS 窗口和稳定复现前，禁止使用“已验证”“具备预测优势”“命中率可靠”等表述。

## 历史重建原则

验证以 15m 已收盘 K 线的收盘时间建立决策网格。对每个 `decisionAt`：

1. 每个周期只截取当时已经收盘的数据；
2. 每周期最多向前提供：1m 2,000 根、15m 800 根、1H 400 根、4H 400 根；
3. v0.6 分析模块再执行同样的未来过滤、严格校验、连续后缀和 200 根门槛；
4. 特征快照和未来标签分两个阶段构建；
5. 快照明确标记 `HISTORICAL_RECONSTRUCTED`，不冒充当时实时保存的 `LIVE_OBSERVED`。

未来标签来自随后已经收盘的 15m K 线路径，观察窗口为：

- 15 分钟：1 根 15m；
- 1 小时：4 根 15m；
- 4 小时：16 根 15m；
- 24 小时：96 根 15m。

路径缺失返回 `GAP`，尚未走完观察窗口返回 `PENDING`，不以零收益或最后已知价格替代。

## 60/40 时间切分与 24 小时 purge

全部成功重建的样本按时间排序，使用一次固定切分。交互 API 为控制首次计算成本，在最近 960 个连续 15m 决策点中以最新样本为锚、每 4 根系统抽取一次，共请求 240 个重建点；保留的 `gridIndex` 仍按原始 15m 间隔计数，因此 HAC lag 的时间含义不变。这个固定抽样不根据结果挑选样本。

- 前 60%：训练描述区，只用于报告分组表现；
- 后 40%：锁定 OOS 区间，不参与阈值、方向标签或分箱选择。

最大标签窗口为 24 小时，因此切分边界前 24 小时内的训练样本会被 purge，防止训练样本的未来标签穿越到锁定区间：

```text
training sample eligible only if decisionAt + 24h <= splitAt
```

这仍然只有一个 OOS 区间。当前要求的最少独立 OOS 窗口数为 4，而当前实现最多只能声明 1 个，因此无论单次结果是否好看，都只能标记为探索性。

## 重叠样本与 HAC

15m 决策网格上的 1h、4h、24h 标签存在重叠，普通独立同分布标准误会过于乐观。报告使用 Newey-West/HAC 长期方差估计，预设 lag 为：

| 标签窗口 | HAC lag（15m 网格） |
|---|---:|
| 15m | 1 |
| 1h | 4 |
| 4h | 16 |
| 24h | 96 |

报告同时输出原始样本数、HAC 有效样本数、标准误和 95% 置信区间。统计状态至少要求：

- 原始可推断样本 `>=30`；
- HAC 有效样本 `>=30`。

达到这两个门槛只表示“可以展示探索性统计”，不代表通过正式验证。

## 分组与指标

当前报告按以下离散特征分组：

- 综合方向 `overallBias`
- 4H 环境 `regime4H`
- 4H 结构 `structure4H`
- 趋势强度分箱
- 多周期一致性分箱
- `NO_CHASE / CHASE_ALLOWED`

未来结果包含市场收益、方向化收益、方向命中、MFE 和 MAE。中性方向没有方向化命中含义，此时仅保留市场收益。

这些分组是在当前固定实现上做的描述，不得根据锁定 OOS 的结果回头修改阈值，再继续称其为同一锁定验证。

## 数据保留导致的覆盖限制

- 1m 本地只保留最近 7 天；
- 15m 本地只保留最近 90 天；
- 1H/4H 保持现有长期研究数据。

所以在较早的 15m 决策网格上，1m 通常不存在。验证会把 1m 特征记录为缺失并降级，不补零、不使用未来 1m 回填，也不声称早期样本拥有完整四周期覆盖。超过 90 天的 15m 标签和决策网格同样无法仅凭当前滚动库重建。

分析快照的 180 天保留与 K 线保留不是一回事：180 天只适用于实际运行时持久化的紧凑 `LIVE_OBSERVED` 分析快照，不会凭空恢复已经裁剪的 1m/15m 原始 K 线。

## 为什么 PBO 和 Deflated Sharpe 不可用

PBO 和 Deflated Sharpe 需要预先登记的多配置试验空间、每个配置在独立窗口的表现和完整试验次数。本项目当前只有一个冻结模型，没有可审计的多配置试验账本。用虚构的配置数量或事后挑选的变体计算这些统计量会制造错误安全感，因此 API 明确返回不可用。

## API 与缓存

`GET /api/market-analysis/validation` 根据本地四周期 K 线重建报告。交互端点固定使用最近 960 个 15m 决策点和步长 4，并按确认 K 线全序列的聚合内容指纹缓存结果 15 分钟；较旧回补、同时间戳 OHLCV 修正都会令缓存失效。1m 指纹只计算到最近已完成的 15m 决策，因此两次 15m 收盘之间的新 1m K 线不会无意义地重建旧报告。并发标签页通过 single-flight 锁共享同一次重建。本次实测首次计算约 25.95 秒，随后相同数据命中缓存约 0.045 秒。前端不会等待这个慢任务才显示当前结论，验证区独立加载。缓存和抽样只控制运行成本，不改变 point-in-time 过滤、未来标签分离或 `validationPass=false`。
